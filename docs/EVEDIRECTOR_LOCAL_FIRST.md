# EveDirector Local-First Validation

This document defines the first practical implementation path for the
EVEMISSLAB OpenMontage fork.

The immediate goal is not cloud deployment, multi-user hosting, or paid video
providers. The goal is to establish a reproducible local baseline that proves:

1. the machine can run the required runtimes;
2. OpenMontage's project, checkpoint, event, and Backlot contracts work;
3. the Remotion composer can produce a real MP4 without API keys;
4. the local board can display a production workspace;
5. paid or private providers can be added only after the zero-key path is sound.

## Why zero-key validation comes first

A successful Backlot simulation does not prove that a video can be rendered.
A successful Remotion render does not prove that the agentic pipeline and
checkpoint contracts work.

The local-first harness therefore keeps these tests separate:

| Test | What it proves | What it does not prove |
|---|---|---|
| `doctor` | Python, Node, npm, npx, FFmpeg, packages and source fixtures are visible | A render will be aesthetically good |
| `smoke` | Demo discovery and Backlot project/checkpoint/event writing work | Cloud AI providers work |
| `demo` | Remotion produces a real H.264 MP4 without API keys | The result used generated video models |
| `board` | The local Backlot server can open a project workspace | The board is a full editor |
| `all` | The complete local zero-key validation sequence runs | Paid provider credentials are configured |

## Branch

Development branch:

```text
evedirector-local-first
```

The older `evedirector-web-runtime` branch remains an independent future
experiment and is not required for this local path.

## Prerequisites

- Python 3.10+
- Node.js 18+
- npm and npx
- FFmpeg
- Git, recommended for updates

Cloud API keys are not required for the first test.

## Initial setup

From the repository root:

### macOS / Linux / Git Bash

```bash
make setup
```

### Windows PowerShell

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Set-Location remotion-composer
npm install
Set-Location ..
python -m pip install piper-tts
Copy-Item .env.example .env -ErrorAction SilentlyContinue
```

Piper is optional for the first Remotion-only demo. The first rendered demo can
run without TTS or any cloud provider.

## One-command Windows path

```powershell
.\scripts\evedirector-local-first.ps1 doctor
.\scripts\evedirector-local-first.ps1 smoke
.\scripts\evedirector-local-first.ps1 demo
.\scripts\evedirector-local-first.ps1 board
```

Full sequence:

```powershell
.\scripts\evedirector-local-first.ps1 all
```

The default real render is:

```text
code-to-screen
```

Choose another checked-in zero-key demo:

```powershell
.\scripts\evedirector-local-first.ps1 demo -Demo world-in-numbers
.\scripts\evedirector-local-first.ps1 demo -Demo focusflow-pitch
```

## Outputs

### Backlot smoke project

```text
projects/evedirector-local-smoke/
```

The simulator writes:

- `project.json`;
- stage checkpoints;
- script artifact;
- scene plan artifact;
- asset manifest;
- synthetic image assets;
- event history.

These assets validate the production-state contract. They are not presented as
real model generations.

### Real zero-key MP4

```text
projects/demos/renders/code-to-screen.mp4
```

This file is rendered by Remotion from checked-in React composition data. It is
a real H.264 video and does not require a video-generation API key.

## Opening Backlot

```bash
python -m backlot open evedirector-local-smoke
```

Default address:

```text
http://127.0.0.1:4750/p/evedirector-local-smoke
```

Backlot remains a read-only, disk-derived production board at this stage.
EveDirector's future editable workflow, infinite canvas, and timeline are not
part of this baseline.

## What can run without paid AI APIs

The initial local path can validate or produce:

- Remotion text and data-driven animation;
- charts and motion graphics;
- FFmpeg composition and inspection;
- local project/checkpoint/event storage;
- Backlot live observation;
- synthetic test images generated by local Python drawing code;
- optional local Piper speech when its voice assets are available;
- local or royalty-free assets supplied by the user.

It cannot produce Veo, Sora, Kling, cloud image generation, or cloud TTS output
without the relevant provider credentials.

## Secret policy

The local-first harness:

- does not read secret values;
- does not print `.env` content;
- does not require `.env` for the zero-key path;
- treats cloud providers as a later capability layer;
- keeps generated projects under the ignored `projects/` directory.

Never commit:

- `.env`;
- service-account files;
- API tokens;
- provider cookies;
- generated private media.

The repository `.gitignore` already excludes common secret and project paths.

## Acceptance criteria for Phase L1

Phase L1 is complete when the user's own machine can demonstrate all of the
following:

1. `doctor` reports all required checks as ready;
2. `smoke` creates `projects/evedirector-local-smoke/`;
3. Backlot displays the simulated project;
4. `demo` creates an MP4 under `projects/demos/renders/`;
5. FFmpeg can inspect the output;
6. no API key is required;
7. failures are recorded with the exact failing command and exit code.

## Implementation sequence after Phase L1

### L2 — One real EVEMISSLAB source document

- select one short Markdown article or product description;
- create a source-grounded script;
- map it to a simple scene plan;
- render with Remotion, user-owned images, diagrams, and optional local TTS;
- inspect the production through Backlot.

### L3 — Local AI-assisted production

- connect a local language model or local coding Agent;
- allow it to read OpenMontage skills and pipeline definitions;
- retain human approval gates;
- continue using only local or user-supplied media where possible.

### L4 — Optional provider adapters

Only after L1–L3 are stable:

- add one image provider;
- add one TTS provider if local speech is insufficient;
- add one video provider only when motion generation is actually necessary;
- set explicit project and daily cost limits.

### L5 — EveDirector control plane

- introduce Project Graph mapping;
- add editable workflow projection;
- add infinite canvas projection;
- add timeline projection;
- keep OpenMontage as the production execution layer.

### Future — Private MCP and hosted runtime

Private MCP and web deployment remain independent future projects. They should
reuse the stable local capability boundary rather than determine the current
architecture.

## Current boundary

The local-first branch intentionally does not add:

- cloud hosting;
- account systems;
- remote secret storage;
- arbitrary Shell tools;
- private MCP connectivity;
- paid provider keys;
- automatic public publishing.

This is deliberate. The first milestone is a reproducible local production
floor, not a complete service.
